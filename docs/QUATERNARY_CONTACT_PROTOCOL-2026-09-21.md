# 四进制候选状态与接触关系：独立原型协议

发起思路属于 Qinzi27。用户澄清：内圈 `(1,2)` 的 2 表示“非1”的最小代表，
仍保留名字 2、3、4；不能未经说明把代表 2 写成唯一颜色承诺。本协议在正式
实验前固定，保留旧 `mother-peer-structural-reuse-v1` 全部源码与历史结果。

## 语义与输入范围

- 四位四进制字 `d1 d2 d3 d4` 的四个位依次对应名字 1、2、3、4。
  每位 0 表示排除，1 表示尚可，2 表示当前约束下的唯一候选，3 表示显式锚定。
  多候选字只含 0/1；单例只有一个 2 或 3，其他位为 0；0000 表示空域。
  外部提供的单例/域是输入假设，不伪装成程序已经证明的事实。
- 最小代表只供显示，不成为锚点、不删除其他名字。两个相邻变量可以暂时
  显示同一个最小代表；显示值不能作为完整配色输出。
- 每条有向线保留独立 ID、左右侧身份和类型。真实分割线产生异名约束；
  桥必须左右为同一个侧身份，不产生异名约束。仅点接触不自动产生异名。
  输入逻辑同名 `equal_names` 不合并几何身份，也不视为已经证明的推论。
- 单侧四位字只记录候选状态。左右允许组合用 4×4 布尔关系另存，打包为
  16 bit / 八位四进制；反向取关系转置。八位关系字是位打包，不沿用每位
  0/1/2/3 的单侧状态解释。多侧联合条件仍需更多关系或结构化约束。
- 先支持显式给定的接触模型；不自动猜手绘交点、重建全部母线或平面嵌入。
  例子对应用户说明的局部含义，不声称已经精确转录整张图。

## 算法与保证范围

原型仅做候选域/有向关系的可靠删减，复用已存在的二元路径一致核心。
没有取最小色提交、搜索、回溯或精确 oracle 救援。输出为 solved、
underdetermined、conflict；solved 必须逐原接触约束核查，underdetermined
不声称存在全图合法延拓。四进制是一种编码，非新增颜色，也不是四色上界证明。

## 正式有限检验

1. 对 1–4 个变量枚举全部简单无向接触图，各变量取未锚定或锚定1/2/3/4的
   全部模式，共 41,055 个模型。每条抽象边表示一条分割线，不冒充完整绘图历史。
2. 两变量的全部 16×16 个候选子集，分别测试真共边、逻辑同名、仅点接触，
   共 768 个模型；另检查单侧桥的全部 16 个候选子集。
3. 独立枚举每个模型初始域的完整笛卡尔积，检查全部合法赋值的一元和二元
   投影被保留；以独立集合关系实现计算固定点，核对核心传播结果。空域和
   真矛盾不当成解析错误或成功。单元测试核对全部256个四进制字的规范合法性。
4. 运行8个具名局部例子，保存完整输入、初态、传播、编码、允许组合和独立核查。
5. 所有输入清单、源码及本协议哈希先写入 manifest，再运行实验；输出独占写入
   新文件。每模型至多4个变量，最多256个完整字面赋值；不做颜色对称归并。
   本轮没有改进一般求解能力或运行复杂度的预设结论。

新增文件仅为独立原型、试验入口、例子与测试。后续若接入主算法，需另立
版本、明确剩余多候选如何完成，以及重新检验全部历史基线。
