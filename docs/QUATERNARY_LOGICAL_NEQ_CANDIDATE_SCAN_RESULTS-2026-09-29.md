## 1. 本轮实际检查了什么

对原始图G，以S表示初始锚点及此前实际提交的颜色；E_G(S)表示满足真实共边
约束和S的全部合法四色赋值。每个状态先检查 E_G(S) 是否为空，再对未决面v
的每个保留颜色c检查 E_G(S ∪ {v=c})。所有查询仅使用原始separator边与这些
显式承诺，学习EQ/NEQ、候选删减和推导单例都不进入oracle前提。

状态清单包含初态及每个真实事件的after-phase；已提交trial算持久状态，
被拒绝trial不算。单例不重复逐色查询，但无待查候选的终态也有基础查询。
本批855个无候选状态均为已完成终态。完整目标清单在任何正式新查询前冻结。

本轮确认的是：对这批已保存状态中的每个保留单候选，**各自存在**至少一个
完整见证。不同候选可以由不同配色支持，因此不能推出多个任意候选同时兼容，
也不能推出改选一个颜色之后继续运行所到达的新状态仍具有同样性质。

## 4. 旧七个坏候选为何没有再次出现

仅比较相同19面原图、相同初始化与完整实际承诺集合。
[只读路径对照包](../outputs/quaternary-logical-neq-candidate-known-path-comparison-2026-09-29.json)
保存旧、新检查点哈希，七个旧候选的原始状态，以及两模式所有持久状态的
实际承诺、全部19面候选域及对应关系。它不运行生产、传播或oracle，且独立于
本轮扫描汇总；包中的新扫描结果字段保留null，实际结果以本轮正式报告为准。

- 旧单锚初态 `{S1=1}` 的 `S10=1`，以及旧双锚初态 `{S0=1,S1=2}` 的 `S10=2`，
  在新版相同实际承诺下已被删除。这两个目标属于明确的提前推理收益。
- 另五个旧坏候选为 `{S1=1,S16=1}` 状态下的 `S3=2/3/4`、`S4=1`、`S5=1`。
  新版先提交S10=2，整条实际路径不再经过这个旧状态；不能把这五项算作
  相同前提下的规则修复。其中旧S3三个目标可被条件反证，旧S4/S5仍条件未决。
- 单锚从第二次提交起，两版承诺集合及全部候选域逐阶段相同。双锚新版初态
  候选域等于旧版拒绝S10=2之后的候选域，此后对应状态也相同。最终配色相同。

因此本轮支持“新版实际路径未检出残余坏候选”。它没有证明旧七项缺口全由新
逻辑规则解决，也没有证明母线调度在一般图上总能避开危险承诺集合。
旧扫描与本扫描的图集、状态路径和分母不同，不报告简单的7→0修复率。

## 6. 意义与下一步

前轮只确认实际作出的3,663次提交安全，本轮另为52,982个未选择候选保留了
完整延拓见证。这加强了对这批实际状态的认识，但不增加生产算法完成数，
也不是速度或原创性实验；离线搜索成本不能混入着色算法的运行收益。

下一步优先检查二元关系矩阵仍允许的**两个面同时取色**是否有完整延拓，
先另立协议冻结范围与资源。不能只把两个单面候选作笛卡尔积，否则会重复
发现已有共边规则早已禁止的色对。发现无支持色对时，区分联合传播缺口与
实际可达的错误承诺；oracle仍只作离线核查。这一步才会回答目前单候选检查
尚未覆盖的“组合起来是否仍然兼容”。几何精度修复继续另列，不混入算法收益。

复现使用新的输出名，避免覆盖本轮档案：

```text
python -X utf8 scripts/validate_quaternary_logical_neq_candidate_scan.py prepare --manifest outputs/my-neq-candidate-manifest.json.gz
python -X utf8 scripts/validate_quaternary_logical_neq_candidate_scan.py run --manifest outputs/my-neq-candidate-manifest.json.gz --output outputs/my-neq-candidates.json.gz
python -X utf8 scripts/validate_quaternary_logical_neq_candidate_scan.py check --manifest outputs/my-neq-candidate-manifest.json.gz --report outputs/my-neq-candidates.json.gz --output outputs/my-neq-candidates-check.json
```

复现需要完整前序来源与检查点。prepare重放旧保存证据；run才执行新候选搜索；
check只复核已保存证据。本轮文件保存在本地，未包含在9月27日先前发布提交中。
