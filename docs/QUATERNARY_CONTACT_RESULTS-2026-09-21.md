# 四进制接触原型：保留“非1”，区分代表与承诺

发起思路属于 Qinzi27。本轮按用户澄清，将图中的第二个名字“2”解释为
候选集合 `{2,3,4}` 的最小显示代表，新增独立原型。原有几何重启算法和
历史实验保持原样。本文件记录实现与核查结果，不宣称新四色证明或一般完备算法。

## 1. 如何把用户的意思存入计算机

四位四进制字从左到右对应名字 **1、2、3、4**；每个位上的符号只取 0–3。
位置表示“哪个名字”，符号表示“这个名字目前是什么状态”，不能混为一谈。

| 四位字 | 保留的名字 | 显示代表 | 含义 |
| --- | --- | --- | --- |
| `1111` | `{1,2,3,4}` | 1 | 尚未排除任何名字 |
| `0111` | `{2,3,4}` | 2 | 非1；没有决定用2 |
| `0011` | `{3,4}` | 3 | 已排除1和2；仍有两个选择 |
| `0200` | `{2}` | 2 | 只剩2，未被记录为显式锚点 |
| `0300` | `{2}` | 2 | 输入显式指定名字2 |
| `0000` | 空集 | 无 | 该域已无允许的名字 |

状态符号约定：0=排除，1=多候选中的一个，2=未显式锚定的单例，3=显式锚定。
外部输入的 `0200` 只是输入限制；只有传播得到的单例才是本次推导结果。
原始输入、初态及显式锚点来源均保存。显式锚点与其他约束冲突时，输出空域和
冲突，仍保留原锚点来源，不伪造一个可用颜色。

四位字有 256 个数值位置，本协议只使用 20 个规范状态：1个空域、11个
至少含两名的集合、4个未锚定单例、4个显式锚定单例。四进制不会增加颜色数。
若只存集合，四个二进制位已经足够；本轮使用四进制是为同时表达状态区别，
尚无压缩率或速度优于二进制的实验结论。

## 2. “保证接触”的具体内容

每条线分别记录 `id / left / right / kind`，候选字不能替代几何邻接输入。

- 真实分割线 `separator`：左右为不同侧身份，允许组合必须异名。
- 桥 `bridge`：左右是同一个侧身份，不添加异名条件。
- 仅点接触 `point_contacts`：记录接触，但不自动添加异名条件。
- 逻辑同名 `equal_names`：限制名字相等，仍保留两个几何身份；外部声明不冒充推论。

例如内侧 I 已为1，A、B 均与 I 共边，且 A、B 也真实共边。结果为：

```text
I: 3000 -> {1}
A: 0111 -> {2,3,4}, 显示2
B: 0111 -> {2,3,4}, 显示2
A--B允许: (2,3), (2,4), (3,2), (3,4), (4,2), (4,3)
```

两个显示代表都是2并非配色冲突，因为程序尚未同时给 A、B 指定名字2。
此时输出 `underdetermined`，`colors=null`，不会把代表数组冒充配色。
若另加显式承诺 `A=2`，则 B 缩为 `{3,4}`，编码 `0011`。
这是新增输入承诺导致的传播，不能从“显示2”自动推得。

单侧四位字只存候选。左右的允许组合另用 4×4 布尔关系记录：
`bit[4*(left_name-1)+(right_name-1)]`。可打包成16 bit，即八位四进制；上例
六对关系为 `12223000`。关系字是普通数值打包，其每位不沿用单侧状态的含义。
反向看同一条线时交换左右身份，并将关系转置。多侧联合状态仍需更多信息。

## 3. 传播为什么不会仅因代表值而删掉解

原型复用既有二元路径一致传播，不取最小名提交、不搜索、不回溯。
对三个侧身份 i、k、j，关系更新形如：

`R(i,j) <- R(i,j) intersect (R(i,k) compose R(k,j))`。

如果一个完整合法赋值给三侧的名字是 a、b、c，那么其 `(a,b)` 和 `(b,c)`
必须分别在两段关系中，因此 `(a,c)` 必在组合关系里，不会被这次交集删除。
从包含所有原始合法赋值的初态出发，这个性质可逐步保持。这是已知关系一致性
操作的可靠性理由；本轮新内容是编码与接触输入的实现和核验，没有新增推理定理。

非空二元关系并不保证存在完整合法赋值。额外范围对照给 K4 的每个侧都输入
`0111`：六条共边要求四侧彼此异名，但总共只允许2、3、4。局部关系可能仍
非空，81个完整赋值却都不合法。因此 `underdetermined` 的准确含义是“未决”，
不能写成“保证可延拓”。K4本身可以四色，这个障碍来自额外排除名字1的输入。

## 5. 如何复现与继续

使用项目的 Python 3.10+ 环境，不需新增依赖。输出文件必须使用未存在的新名字：

```powershell
python scripts/validate_quaternary_contacts_v2.py prepare --manifest outputs/my-quaternary-manifest.json.gz
python scripts/validate_quaternary_contacts_v2.py run --manifest outputs/my-quaternary-manifest.json.gz --output outputs/my-quaternary-run.json.gz
python scripts/validate_quaternary_contacts_v2.py example --id two-neighbors-same-minimum --output outputs/my-quaternary-example.json
python -m unittest discover -s tests -v
python scripts/validate.py --output outputs/my-quaternary-validation.json
```

主实现：[quaternary_contact_model.py](../scripts/quaternary_contact_model.py)。
局部例子：[输入集](../examples/quaternary-contact-prototype-2026-09-21.json)。
这些模型表达手绘图中已经澄清的局部意思，不是整张手绘图的精确拓扑转录。

下一步应先把真实母线/线侧模型导出为这里的接触输入，验证几何身份与共边
对应一致，再单独研究多候选如何完成。若引入主动选名，要对每次承诺检查
可延拓性；若保留完整联合边界状态，则需测量状态数量和计算成本。本原型只
解决“表达和传播时保留可能性”，尚未提供新的通用完成步骤、性能改善或原创性结论。
