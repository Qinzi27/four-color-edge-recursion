# 低色优先与条件传播：计算前协议

本轮按Qinzi27的“通常优先低色”偏好，将具名颜色按1→2→3→4排序。
这是当前侧的名字偏好，不是全图最少颜色数的优化承诺。新代码单独放在
`scripts/quaternary_low_color.py`；旧四进制核心、旧生产策略和报告保持冻结。

## 规则与可证明边界

两个版本共享输入、初始化、选侧顺序和既有二元路径一致传播。
`plain`直接提交当前侧最小候选；`guarded`先临时固定同一个最小候选并传播。
若得到矛盾，则撤去该假设，保存矛盾轨迹，把当前侧候选中这个名字排除，
重新传播并选择。若没有矛盾，则提交这个名字；当试探已经给出完整合法
配色时标为完整见证，否则明确标为`inconclusive`，不声称选择必然安全。

选侧沿用母线`mother-peer`规则。旧规则默认框线两侧均已命名；单锚模式
可能剩下只有框线occurrence的未决侧，因此只在没有任何未决内部母线
occurrence时，按侧ID选一个框线侧。这个fallback写入轨迹；两个版本相同。
本轮没有接入旧Hall、结构同名反证、Kempe或联合边界求解，不能假称完全
复现旧完整生产算法，基线是这里明确冻结的`plain`版本。

排除规则的逻辑：令原约束为F，累计实际承诺为S，已证明删减为L。若
F∧S蕴含L，且可靠传播证明F∧S∧L∧(v=c)矛盾，则F∧S蕴含v≠c。
所以排除c保留全部满足当前承诺的完整解。复制同侧此前传播域中已经
证明的删减也保解。该推理不证明反方向：未推出矛盾，不代表存在完整解。

已提交颜色不回退；临时假设及其撤去明示为条件试探，不能称完全无试探。
每次提交固定一个未决侧，每次排除永久减少至少一个当前候选。在固定有限
输入上这些操作次数有限；另外设显式预算，预算耗尽保留`incomplete`。
四名是输入色盘，未在此证明普遍四色上界或算法完备性。

## 预声明输入

1. 完整保留上一轮manifest的4,144个不同输入key：全部4,096个3×3内部
   单位线段子集和全部49个历史对照，空框重合；不根据本轮结果筛选。
2. 保留旧S10首错前、后的两个具名初始化诊断，传入实际旧承诺，不传旧
   派生域或完整目标色。首错后初始化本来UNSAT，另列，不算新算法失败。
3. 新种子20262201–20262208，两族各8条加线历史：既有guillotine生成器
   前8次合法矩形切分；完整弦族从左右框边20..580整数位置各无放回抽8点，
   按配对顺序连接。逐历史保留0..8步，16条历史、144个前缀引用、129个
   去重输入；这些输入在未看新算法结果时生成，不按解色难易筛选。
4. 与旧库按规范无向笔画集合key比对后，128个输入key是旧4,144库未见的，
   合并共4,272图。未声称图同构去重，旧构造族新种子也不是新独立图族。

每图运行单有界面锚1、旧框线双锚1/2两模式，分别比较plain/guarded。
两项旧首错诊断另加：每策略8,546场景，总17,092次运行。无需完整旧色
往返，因为本轮评价主动完成。4,112条历史及28,816个前缀引用全部保留；
每个前缀从其模式初始化重新命名，不继承前缀旧颜色，不宣称枚举所有顺序。

预先固定真实几何、全部锚点、输入来源及代码/测试/本协议哈希后，再跑
正式实验。开发时允许使用旧S10和小fixture检查接口；这些烟测单列，不能
与正式结果合并。新种子输入仅在源冻结后用于新算法结果测试。

## 独立核查与资源

- 两策略都先完成生产，再开始离线审计；不交换颜色，不借oracle补救。
- 真实几何复用上一轮适配与独立几何审计，继续记录其共享Node平面化、
  母线分组及1e-5像素精度边界。调度核查复用母线选择器，不称完全独立。
- 每个主阶段及条件试探的完整二元删减轨迹由独立字面集合实现复核；
  撤假设、持久排除、承诺链、最低候选优先和停止原因分别核查。
- 初始域笛卡尔积≤262,144时，枚举原始真实邻接与初始锚点的全部合法解。
  后续按累计实际承诺过滤这些解，逐阶段核对全部一元/二元投影未被删掉。
  超限为`not_run`，仍做轨迹与逐步精确核查；不能称全部场景全赋值穷举。
- 精确oracle仅接收原始真实共边、初始化与实际承诺（核查试探时另加一个
  临时颜色），不接收推导域或排除结论。初始化和每步承诺前后独立核查；
  SAT保留完整见证，UNSAT保留无解树并另验，首次SAT→UNSAT完整记录。
  每次最多200,000节点，耗尽为unknown，不能算无解、安全或通过可延拓性。
- 固定4进程、每批16图；每次生产最多128次实际提交和512次条件试探。
  生产完成/冲突/未完成、核查通过/错误、oracle已知/未知分开报告。
- 保存所有运行的完整phase/event/oracle证据到独占新分片；总报告绑定
  分片哈希和精确覆盖。实现或审计异常保留现场后停止该版本，算法冲突作为
  正常负结果继续收集。不得静默换规则重试后拼接成功集合。

## 结果评价

分初始化与已知/新增输入报告双方完成、仅guarded完成、仅plain完成、双方
未完成；主动提交是否安全、排除是否保解、额外试探/传播/时间成本分别报告。
若出现新guarded失败，保留原图与首错证据，再做符合声明输入条件的缩减，
明确缩减范围而不宣称全局最小。若只有修复而未见退步，也仅限本次有限范围。
本轮不作原创性结论或已知最优算法速度比较。
