## 1. 为什么单候选全部有解，两个候选仍会冲突

设G是原始真实共边约束图，S是初始化锚点与实际累计落名；E_G(S)表示满足它们的
全部合法四色赋值。[前轮单候选普查](QUATERNARY_LOGICAL_NEQ_CANDIDATE_SCAN_RESULTS-2026-09-29.md)
确认每个保留的单候选各自有解，即 E_G(S∪{u=a}) 非空。它没有要求不同候选使用
同一份配色见证。本轮另查 E_G(S∪{u=a,v=b}) 是否为空。

四位候选码记录一个面的剩余名字；二元矩阵记录两个面的允许色对。编码可以准确
保存已知限制，但编码形式本身不保证所有全局限制都已被推导出来。本轮发现的
1,814项已经通过当前二元闭包，因而不只是重复发现真实相邻面不能同色的约束。

oracle只读取原始separator边、S及该次两个字面假设；学习EQ/NEQ、传播域、
推导单例、关系矩阵和拒绝删域均不作为精确查询前提。oracle答案没有回流生产端。
条件传播诊断则保留保存阶段的完整document，增加两个假设，并独立重放其轨迹。

## 4. 11项未检出的条件限制

全部来自原图key `8070783fd68d…` 的单锚state 0 / phase 0，实际前提仅 `{S1=1}`。
以下各对均假设两端取1，均为both_min、not_next_choice；单独取1各自SAT，联合
UNSAT，但条件传播inconclusive：

`(S4,S6), (S4,S7), (S4,S14), (S4,S16), (S5,S8), (S5,S14), (S5,S16),`
`(S7,S14), (S8,S14), (S9,S14), (S14,S18)`。

[已知图证据包](../outputs/quaternary-logical-neq-pair-known-case-2026-09-29.json.gz)
保留完整原始输入、上游引用、全部持久状态候选域与矩阵、精选缺口的完整证据，
以及所有451项无支持色对身份和真实后续事件。单锚188项中177项已排除、11项
未决；双锚263项均已排除。

例如S4=1与S16=1各自可行，联合UNSAT证明树28节点；S5=1与S16=1各自可行，联合
UNSAT证明树46节点。两组的初始二元矩阵均为65535，允许全部16个色对。
真实顺序先S10=2、再S16=1，此后S4/S5都只剩{2,3,4}。这解释了前轮单候选扫描
为何没有检出残余坏候选，却不说明换一种选择路径仍有相同安全性。

### 一个可以直接核查的结构解释

[奇轮诊断包](../outputs/quaternary-logical-neq-pair-odd-wheel-diagnostic-2026-09-29.json)
对第一项未决 `(S4=1,S6=1)` 保存了原始边证据。此处讨论的是以面为顶点的真实
邻接约束图，不是原始地图上的边界环。

1. 在S1=S4=S6=1下，中心S3和轮缘S0、S2、S17、S18、S5各有一个取1的真实邻面，
   因而六个顶点都只能用{2,3,4}。阻色邻面依次为S4、S1、S1、S1、S6、S4。
2. 原始边包含中心到全部轮缘的五条辐条，以及闭环
   `S0–S2–S17–S18–S5–S0` 的五条边。
3. 中心取任一剩余颜色后，五个轮缘顶点都只能从另外两色中选择。
4. 奇数环不能用两色闭合，故假设组合矛盾。

因此在本图上有 `(S1=1) ⇒ ¬(S4=1 ∧ S6=1)`。证据只使用10条轮图真实边、
6条真实邻接阻色见证和三个字面前提，没有将oracle搜索树当作结构推理前提。
实际原图及S1=1本身可四色；矛盾属于这两个额外假设的联合。

这不是全局S4≠S6的证明，也不是新数学定理。这里只提取了这一项具体奇轮证书，
尚未证明相同结构能覆盖其余10项，尚未将新冲突规则接入生产版。

## 6. 下一步的具体改动方向

优先另立带证书的“三色域奇轮冲突”规则：若真实邻接中存在奇轮，且全部轮图
顶点的可靠候选域包含于同一个至多三色集合，则可以证明当前假设矛盾。将本轮
11项作为已知回归目标，逐项报告修复或持续未决，不预先宣称全部解决。增加偶环、
缺失辐条／轮缘边、颜色排除前提不足等控制，并枚举小构形的合法赋值检查可靠性。
随后在独立新增输入上复核，分别测覆盖、实际提交安全、完成数和资源成本。

对已有1,803项可靠条件反证，可另研究带完整前提的色对禁配记录。若矛盾由阶段
document D加上u=a、v=b推出，只能先记录 `D ⇒ (u≠a 或 v≠b)`；要用原G和实际S
作为较弱前提，必须沿EQ/NEQ及删域证书验证它们足以推出D。不能删成整对面异名，
不能丢弃颜色或锚点条件跨状态复用，不能把离线oracle结果直接灌入生产端。

维持低色偏好和母线调度，每次实际落名前只接受有证据的排除。新规则首先检验
结构推理覆盖，是否节省试探、增加完成或改变实际选择均须另测。本轮没有新的
四色证明、一般无回溯安全保证或原创性结论；31°几何问题继续单独处理。

复现使用新输出名，避免覆盖档案：

```text
python -X utf8 scripts/validate_quaternary_logical_neq_pair_scan.py prepare --manifest outputs/my-neq-pair-manifest.json.gz
python -X utf8 scripts/validate_quaternary_logical_neq_pair_scan.py run --manifest outputs/my-neq-pair-manifest.json.gz --output outputs/my-neq-pairs.json.gz
python -X utf8 scripts/validate_quaternary_logical_neq_pair_scan.py check --manifest outputs/my-neq-pair-manifest.json.gz --report outputs/my-neq-pairs.json.gz --output outputs/my-neq-pairs-check.json
```

复现需要完整前序来源及检查点。prepare核对上游保存证据；run执行新的离线搜索；
check只重放落盘证据，不重新搜索或传播。本轮成果保存在本地，尚未提交或推送。
