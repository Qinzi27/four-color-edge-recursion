# 最小数字优先：当前规则是否已经这样选名？

本轮提出者澄清“最低权重”指**优先使用数字最小的颜色**，不是优先处理约束最少的线。
这里检验的是：保留现有选线顺序、当前整图重启和候选过滤，只把已选线侧的取名写成
`c = min(D)`。不把它混同于“跨所有待处理线，先找能取 1 的线”，后者会改变选线顺序。

本轮没有修改求解模块。新脚本从每次决定之前的实际域读取候选和已用名，
检查是不是已经取最小数字，而不只看最终图或相信轨迹中的自报字段。

## 2. 为什么“复用优先”在当前算法中等价于直接取最小数字

原表达式为：

```python
min(domain, key=lambda c: (c not in used, c))
```

`used` 是当前所有单候选侧的名字集合，不是母线数量，也不是祖先禁用名累计。
在任意外部状态中，上式未必等于 `min(domain)`；例如 `used={1,3}`、`domain={2,3}`，
复用优先取 3，而数字最小取 2。但这个缺口状态不能未经证明就视为当前算法可达。

**当前两锚重启规则的等价性论证：**

1. 初始只固定外 1、首内 2。交换尚未使用的名字 3 和 4，不改变输入约束。
2. 单候选排除、Hall 集合预留、关系求交／合成／转置均保留该交换对称性。
   因此首次主动引入 3 或 4 前，每个域要么同时含两者，要么同时不含两者，
   不可能只推导出单候选 `{3}` 或 `{4}`；此时 `used={1,2}`。
3. 若下一次主动选择需要引入新名字，则两者同时可用，规则先选 3。
   之后所有继续落名的非冲突状态保留锚 1、2、3，`used` 只可能再增加 4。
4. 所以每次主动落名前，已用集合只能是 `{1,2}`、`{1,2,3}` 或 `{1,2,3,4}`。
   对这样的数字前缀集合，所有已用名都小于所有未用名，因此两种排序表达式相同。

这只证明**当前算法中的两个取名表达式等价**，不证明它们一定安全。
不包括外部非前缀预着色、不对称名单约束、冲突后不再执行决定的残留域，
也不自动适用于其他历史版本的命名程序。

## 5. 应完善的条件，而不是把最小名字叫作错误目标

最小数字可以继续保留为偏好。需要增强的是：**对当前已选线侧，哪些名字真的可继续？**
当前过滤域 `D_A(u)` 是必要条件筛选，保留的名字不一定都存在共同的完整延伸。
理想的安全域可以定义为

\[
E_A(u)=\{c:\text{存在满足当前承诺 A 且 }u=c\text{ 的完整合法命名}\}.
\]

若能不用配色枚举地求得足够的安全信息，才有依据选择 `min(E_A(u))`。
但仅写出这个定义不会给出算法，也不能把未知的 `E_A` 偷换成现在较宽的 `D_A`。
本轮没有用遍历全解或失败重试来计算它。

另一条可能路线是改变先处理哪条线、或在安全依据不足时保留多个侧名的联动关系。
本轮都没有实现，不能提前声称解决全部地图。最小数字、最少颜色种类和总能完成，
是三个不同目标。
