# 2026-09-18：条带链定理与同步改名困难例

发起思路：Qinzi27。研究方向：用左右符号命名有向分割线，插线改变端点与侧延续后，允许有关旧线名同步更新。

## 本轮结果与边界

1. [条带链定理](STRIP_CHAIN_THEOREM-2026-09-18.md)：固定双锚、没有额外弦的链结构中，保持该结构的每次分割均可确定性完成。选择较短一段同步换名；未拆旧侧类的最少改名数为 `min(i-1,n-i)`。一般 n 的保证来自证明，不来自有限测试。
2. [9 侧困难例](HARD_CASE-2026-09-18.md)：seed 20260927 可通过一个三节点依赖链修复。至少需要改两个未拆旧侧；给出的结果达到该界。三次基本交换可包成一次原子提交，不是要求用户画三次线。
3. 条带链代码没有着色搜索；困难例诊断**明确使用有界搜索**。后者隔离在 `scripts/`，没有导入网页，也不代表提出者的一般命名算法已经完成。
4. 新增的依赖证书校验器不搜索：接受显式候选新名，构造全部旧符号阻塞依赖，确认无环后顺序执行，再核验全部线名。仍未解决“如何不搜索地选择候选并保证无环”。

## 重现上一轮临时诊断

固定输入是旧报告 [construction-validation-2026-09-08.json](../outputs/construction-validation-2026-09-08.json) 的 160 个 guillotine 首次阻塞状态，连续种子 20260908–20261067。不是重新采样，不剔除失败。

| 诊断允许的动作 | 存在修复的首次阻塞状态数 |
| --- | ---: |
| B：旧图一次完整双色分量互换，再用旧分割规则 | 62 |
| C：先分割，暂不计新线异名，再互换仅含一个子侧的完整双色分量 | 95 |
| B 与 C 的交集 | 5 |
| B 或 C | 152 |
| 对剩余 8 例再尝试 B→C | 额外 7 |
| 以上仍失败 | 1：seed 20260927 |

成功互换均固定外侧内部符号0。B、C互不包含；本轮不是把“切后”宣称为“切前”的通用替代。

上述最后一例的切后 H 上，允许任意完整双色分量交换（不含外侧），精确标签 BFS 的新状态层大小为 `1,5,15,31`。距离0–2无成功，距离3有12个成功状态。因此**在这个明确基本操作集合中**最短为3。正式报告到首个成功完整层停止，共52个状态，不声称穷尽一般地图或所有未来分割历史。

另一个小型穷举器检查新图10侧、外侧固定0的全部合法四色命名，得到30个；最少改变两个未拆旧侧，恰有一个达到最小值。它是独立研究 oracle，不为网页填色。

## 文件与复现

- `fourcolor/strip_chain.py`：受限规则，只用 Python 标准库，输入输出不可变，侧类ID与符号分开。
- `tests/test_strip_chain.py`：4920个单步实例（n=1..40、所有切位、固定外侧的6种符号排列）、40次连续分裂、非法输入/不可变性检查。
- `scripts/rename-diagnostics.mjs`：保存原图边与旋转、线侧映射、每次改名、最终有向线名；报告含源输入SHA256。几何映射限定于轴对齐矩形，其他形状明确拒绝。
- `tests/renaming.test.mjs`：计数回归、互补机制、有限搜索边界、DAG证书、环依赖拒绝、外侧固定及输入不变。
- `scripts/validate_renaming.py`：独立 Python 验证；从旋转重建侧轨道，重算修复计数与最短层，验证最终线名而非信任 JavaScript 的通过标记。
- `tests/test_renaming_validation.py`：正式报告重验、源摘要篡改、部分分量、缺失依赖、错误线名、错误最短层及拒绝覆盖的回归检查。
- 当前正式见证：[renaming-round-2026-09-18-v2.json](../outputs/renaming-round-2026-09-18-v2.json)。无v2后缀的同日文件保留为增加依赖证书前的检查点。

正式v2源摘要按 UTF-8 文本、仅 CRLF→LF 规范化后计算，避免 Windows/Linux 检出换行不同造成伪失败；不规范化其他空白或数据。同日早期检查点使用原始字节摘要，不作为当前校验器输入。

项目根目录，Node 20+、Python 3.10+，无需安装新依赖：

```sh
npm test
python -m unittest discover -s tests -v
python scripts/validate.py --output outputs/validation-my-renaming-run.json
node scripts/rename-diagnostics.mjs --output outputs/renaming-my-run.json
python scripts/validate_renaming.py --input outputs/renaming-my-run.json --output outputs/renaming-independent-my-run.json
```

每次重跑给新输出文件名；新增诊断/独立检查器拒绝覆盖已有报告。旧 `validate.py` 本身未更改，运行时务必指定尚未使用的输出路径。

## 最终验证

- Node：51项测试通过，包括重新生成整个报告并逐项对比保存见证。
- Python：84项测试通过；条带链4920个单步实例包含在其中的专项测试内，不是另计4920个测试函数。
- [独立验证报告](../outputs/renaming-validation-2026-09-18-v2.json)：重建320份新旧平面图，核验167份修复/最优证书；困难例全部78个H合法命名均在当前双色交换连通类中，完整层为 `1,5,15,31,26`。这些结论只针对这个小图。
- 独立检查器从输出的边与旋转重建侧轨道和矩形谱系，没有独立重写通用浮点求交引擎。
- 旧报告、旧规则及旧网页均保留；新脚本与网页没有求解调用关系。

## 下一步，而不是已经证明的内容

优先研究“唯一阻塞者 → 下一阻塞者 → 终端空缺”的确定性链识别：规定目标符号选择、重复侧检测、环或多阻塞的停止条件。先证明所支持情形的安全性、终止及范围，再沿完整输入历史测试；不要只重放第一次阻塞后宣布地图完成。

既有双色分量交换通常称 Kempe change；本文不主张该操作的新颖性。可参照 [Matsumoto, 2026, Definitions](https://kam.mff.cuni.cz/~spring/media/papers/6/KempeEquivalentNonOrientable.pdf)。本轮是在项目表示与受限构造上的形式化和实现，不是一般四色新证明。
