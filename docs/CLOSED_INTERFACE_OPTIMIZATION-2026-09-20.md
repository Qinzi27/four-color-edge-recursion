# 闭合接口程序：色名压缩与单接口分解

2026-09-20。接续 Qinzi27 提出的“从最内闭环出发”及“能否真正优化求解程序”。本轮将可以安全收起的局部结构做成独立、可运行的精确求解程序，并以旧精确前沿程序作为同任务对照。原线侧命名算法及历史失败记录保持原样。

**研究定位：这是已有数学原理在本项目中的正确实现与性能检验，不主张新的四色算法原理。** 从内起步并不自动说明接口简单；本轮依据真实面邻接约束识别可分离的块。

## 1. 输入和三个对照版本

输入是完整已知的图 G=(V,E)、固定可用颜色数 q∈{1,2,3,4}、顶点处理顺序。地图输入中，顶点表示面，边表示两个不同面必须异色。原地图桥的同面两侧不生成自约束；普通图 API 若实际收到自环则判不可着色。

| 版本 | 实际保存内容 | 改变的因素 |
|---|---|---|
| `named` | 每个带色名边界赋值及一个内部见证 | 冻结旧精确前沿基线 |
| `orbit` | 每种边界相等模式及一个内部见证 | 只消除整体换色冗余，顺序相同 |
| `blocks` | 每个双连通块内运行 orbit，再对齐共享面 | 额外利用单接口分解 |

三个版本解决相同的普通 q-着色存在性问题并返回一个合法解；无失败换算法、无读取旧解。块内仍有明确的精确状态搜索，不能把它称为原先无回溯取名规则。此处 q 是输入，不是免费的最少颜色 oracle。

## 2. 为什么压缩不会丢掉解

对已处理顶点 P，定义前沿 B={v∈P: v 仍邻接未处理顶点}。已离开 B 的内部顶点没有未来邻边；未来只需要知道 B 的颜色关系。

在无预指定颜色、无列表限制、无颜色相关代价时，全部 q 个颜色名可以整体置换。边界 `(2,0,2)` 和 `(0,1,0)` 表示同一相等模式，因此只保留规范模式 `(0,1,0)`。若边界已经使用 r 类，新顶点只需尝试 r 个旧类，及 r<q 时的一种新类。“新类”指边界未出现，不要求整个内部从未使用。

每步加入顶点、检查已处理邻居、删除已完成接口、重新规范化。规范化映射必须扩展为整个 q 色集合的双射，并作用于完整内部见证。否则，例如边 u-v 的旧见证 u=0,v=1，忘掉 u 后只把 v 改为0会破坏这条边。程序保留全局置换，专项测试覆盖这种错误。

这些操作恰好生成旧带色名状态的全部轨道，故可归纳证明每个前缀的可扩张关系保持一致。一个使用 r 类的轨道对应 q!/(q-r)! 个具名状态；q=4 时最多24个。**这是一项常数范围的色名压缩，不消除随接口宽度增长的指数复杂度。**

## 3. 哪一种局部结构可以安全完成

本轮先实现只有一个共享面变量的接口。约束图的双连通块通过割点组成森林，桥视作二顶点块，孤立点视作单顶点块。每个叶块与其余部分最多共享一个面变量 a。

若该块有一个合法 q-着色，则通过整体换名，a 可以取任意一种颜色。因此对父部分传递的关系只是“所有颜色均可”，无需保存该块全部配色。任一块不可着色则全图不可着色；全部块可着色则从根开始，将每个子块的完整见证换名，使共享变量颜色一致，即得到全图合法解。

程序先叶后根计算块，先根后叶组装见证；它不会永久冻结“内圈的初始颜色”。`interface_relation` 字段表示单块关系，整体可行性另外取全部块结果的合取。

这里的单接口是**约束图中的一个共享面变量**，不是原图的一个流端口，也不能由图形“看起来像一个圈”推断。两个接口不能照搬：一块是边 u-v，另一块是路径 u-x-v，分别可二色，但前者要求 u≠v、后者要求 u=v；合起来是不可二色的三角形。下一阶段的双接口至少必须保留同色／异色关系。

## 4. 预先固定的实验协议

- 复用此前63张地图、全部1,917个处理顺序，分别以固定四色和之前独立确定的最少颜色重跑三版本。最少颜色只作实验控制。覆盖所有内起点、三种遍历及原有两次重编号，不挑最好结果。
- 每个 orbit 前缀状态数必须等于旧 named 前缀的轨道数；全部输出解逐边核验。blocks 的局部状态不能冒称同一个全局前缀状态量。
- 耗时单独采用原编号 BFS 的外起点及全部内起点：213个顺序×2种调色板。每个组合三轮，轮换三个版本的运行先后顺序；计入顺序生成、分解、规范化和见证组装，不将候选次数冒充时间。
- Python `tracemalloc` 内存另行测量，只覆盖63图外起点×2种调色板；内存测量不混入普通计时。记录的是受追踪的 Python 分配峰值，不是进程 RSS。
- 保存每轮原始时间、输入和源码 SHA-256。最多17个面的固定语料适合检验实现与初步成本，不能证明大图扩展性、统计总体优势或优于现有先进求解器。

| 每图最少颜色 | blocks 对 named | 82 / 0 / 131 | 0.58 |

所有三个 API 均生成其原有诊断信息，旧 named 程序还为报告计算轨道数；这不是将所有诊断去除后的最低层内核比较。图规模小，计时为微秒至毫秒量级，未固定处理器核心或隔离操作系统负载，三轮结果不能用来宣布稳定的普遍加速倍数。

原图完整蓝线的约束图本来就是一个双连通块，因此 blocks 的额外分解并不减少状态，只增加处理开销。其 orbit 收益来自色名对称性，并非内起点的优势。

最少两色的树是一个明确负对照：任一连通前缀只有一个颜色轨道，orbit 对 n 个面尝试 `2n−1` 次；分块后有 n−1 个边块，每块尝试3次，共 `3(n−1)`，n>2 时反而更多。全部891个受测树顺序均出现这种额外工作；原编号 BFS 的99个树条件中分块也全比 orbit 慢。不能仅依据局部表较小就自动分块。

### 实际内存：记录分配峰值，不用状态数代替

63个外起点条件下，q=4 的 orbit 受追踪分配峰值63个全部更低；最少颜色下43个更低、2个相同、18个更高。blocks 对旧 named 的对应结果为四色23低／40高，最少颜色7低／56高。

例如15面树 q=4，orbit 的受追踪峰值为26,144 bytes，blocks 为28,040 bytes；虽然块内状态峰值从15降为1，保存分解、各块见证和报告所用的内存仍更大。这些数据是 Python `tracemalloc` 追踪范围内的峰值，不是 RSS。

因此本轮常规试用建议明确选择 `--mode orbit`；`--mode blocks` 保留为研究单接口规则和结构收益的可选模式，尚未形成自适应选择器。

## 6. 使用与复现

核心仅需 Python 3.10+ 标准库。命令行接收明确的面邻接约束 JSON，不直接接收画板的 `frame/strokes`。示例中的 `order`、`palette_size` 可指定；省略时从顶点0开始 BFS、允许四色。输出文件已存在时拒绝覆盖。

```powershell
python -X utf8 scripts/solve_closed_interfaces.py --input examples/closed-interface-two-triangles.json --mode orbit --output outputs/closed-interface-example-rerun.json
python -X utf8 scripts/benchmark_closed_interfaces.py --output outputs/closed-interface-benchmark-rerun.json
python -X utf8 scripts/audit_closed_interfaces.py --output outputs/closed-interface-audit-rerun.json
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/validate.py --output outputs/validation-closed-interface-rerun.json
```

`--mode named`、`--mode blocks` 可运行另外两个版本。初版 CLI 未指定模式时使用 blocks 以展示接口分解，进行本轮较稳妥的性能试用时请显式指定 orbit；不会根据输入或失败情况隐蔽切换。CLI 拒绝无法处理的额外约束字段，避免静默丢弃固定色或颜色列表。

## 7. 与已有工作的关系及下一步

颜色分区动态规划已有明确先例：Jiří Fiala，*Graph minors, decompositions and algorithms*，§5.2，印刷页42–43，以颜色分区而非颜色名称记录状态，给出引入、遗忘和合并操作。[作者讲义](https://kam.mff.cuni.cz/~fiala/tw.pdf)，访问2026-09-20。

块分解着色也是经典结论：*Lecture 12: Vertex colouring*，页3，Lemma 6，说明图色数为其块色数的最大值，并以块树上的颜色置换证明。[课程讲义](https://vagdur.github.io/Grafteori-1MA170/lecture12.pdf)，访问2026-09-20。本轮定向核对这两份资料，不声称完成穷尽查新。

本轮贡献是：在本项目中将充分接口落实为程序，保存正确性核验和可重现的正负性能结果。它没有解决原 v4 的不可逆最小取名安全性，也不直接支持原 v4 的多色名锚定；不能把新精确求解器的成功归为旧规则的修复。

后续最具体的方向是双接口关系：在小块上保留 `{同色, 异色}` 中实际可扩张的子集，再证明拼接保持充分性。是否需要更大接口、判断和生成这些关系是否比现有算法便宜，需要单独实验。不能预先承诺其原创性。

## English summary

We implement two exact optimizations for ordinary graph coloring on a fully known constraint graph: quotienting frontier assignments by global color permutations and solving biconnected blocks through single-vertex interfaces. Both use established principles. Full witness permutations preserve internal constraints, and block witnesses are aligned at articulation vertices. Benchmarks separate deterministic state counts, end-to-end elapsed time and traced Python allocation peaks. These modules are independent of the original greedy line-side naming rule and do not establish a new Four-Color Theorem proof or a new worst-case complexity bound.
