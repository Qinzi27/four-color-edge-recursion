# 整条母线重新计算：验证结果与调整方案

思路发起者：Qinzi27。日期：2026-09-18。

## 结论先行

本轮落实了新的研究对象：**一条母线可以穿过中间接线位置继续延伸，接点不另行命名。**
计算细分的原子边不是新的母线；整条线的名字是沿途有序的双侧描述。

- 255 张有限案例的整线表示检查通过；这不是 255 张地图都由新规则自动四色成功。
- 一个具体旧阻塞，在不固定哪侧继承旧名后，由候选约束直接解出，没有回溯或配色枚举。
- 从外圈完全重启，只用强制传播，2 张完成、253 张仍未定；
  再去除未用符号整体换名的重复后，7 张完成、248 张仍未定。
  未定不是不可四色，也不证明用户尚未形式化的其他规则失败。

## 1. 这轮究竟改变了什么

此前点到点草案见 `POINT_TO_POINT_MODEL-2026-09-18.md`，保留以供追溯。
本轮将其中“接点细分”限定为计算实现，不能据此改变母线的研究身份。

表示一条有向母线为 `L(t), 0≤t≤1`，其名字为：

```text
N_L(t) = (left_L(t), right_L(t))
```

保存整条线的 ID、几何方向、各区间的左右侧身份、双侧符号、接线位置和接入顺序。
接点保存各条线出入端口的环绕次序，没有“点颜色”。
同一个符号可命名不同位置的同色侧，不能把符号相等误认为侧身份相同。
程序从线的连接关系导出“同侧等价类”；数学上它们对应地图的面。
因此这里确实以整线为输入和描述主体，但没有声称换一种表示就能消除全局四色相容性问题。

本轮采用明确而有限的续接约定：

1. 内部直线：沿已经画出、连续共线的部分走到最远，穿过 T/X 接点；不跨未画出的空隙。
2. 外框：单独记录为一条闭合母线，从左上角沿屏幕顺时针读取。
3. 弯折/曲线：除上述外框外，本轮不猜测如何在分叉处转弯；需将来提供显式续接关系。
4. 共线重叠：几何合并，但保留原始 stroke 来源。几何母线 ID 不等于绘制历史 ID。
5. 岛屿的虚拟连接只辅助保存侧连接关系，不算用户画出的线，也不制造新分割。

母线反向读取必须**顺序倒转且左右交换**：

```text
N_reverse(t) = (right_L(1-t), left_L(1-t))
```

## 2. 一个可以证明的有限表示命题

给定已经正确细分的有限平面线网、确定的整线续接规则以及全部接线环绕信息，
每条原子实边恰好属于一条母线的一个区间。按母线方向记录该区间双侧属性，
再按反向交换规则展开，可以逐一恢复原子的全部线侧属性。

理由：这只是原子线侧与“母线 ID、区间、左右侧”的一一对应，改变方向时使用一个可逆交换。
不合并丢失区间、侧身份或接线事件，并保留外侧/分量元数据，就不会丢失命名约束。
同侧等名与真正分界异名在重编码前后对应；桥的双侧仍然是同一侧。

这证明了**表示可以无损**，没有证明四个符号一定足够。
只有 `4×3=12` 种局部异名对，也不意味着整条线只有十二种结构；区间序列长度可以增长。

## 3. 重新算出的具体修复

外框为 `900×600`，屏幕坐标向下增大。四条原有内部线：

```text
L1: (0,400)   → (900,400)
L2: (700,0)   → (700,400)
L3: (200,200) → (700,200)
L4: (200,200) → (200,400)
```

旧名字：外侧 1；左上 L 形侧 A=2；内侧 B=1；右侧 R=4；下侧 D=3。
新增线 `L5: (450,200)→(450,400)`，原 B 分成西 W、东 E。

### 错误的额外限制

若先固定 `W=旧B=1`，只看上下两条母线的接入局部：

```text
a=2, b=1, d=3  ⇒  E∈{1,2,3,4}\{2,1,3}={4}
```

但是 E 同时接触 `L2` 另一侧的 R=4。
冲突发生在 `(700,200)→(700,400)`，不是新增竖线的两个接入位置。
因此，**只检验新增线两端，不足以检查整个关联线网。**

### 调整：两侧都撤销旧承诺，再传播整线关联

这个小实验暂保留外侧/A/R/D 的名字，只放开 W/E；这是条件修复试验，
不是冒充从外圈完全重算。全部重算实验另列于下一节。

```text
W 通过旧母线接触 A=2、D=3       ⇒ C(W)={1,4}
E 通过旧母线接触 A=2、D=3、R=4 ⇒ C(E)={1}
新增 L5 是真正分界，W≠E        ⇒ E=1，W=4
```

没有尝试失败后回头，也没有枚举配色组合。新竖线向下，其左侧在东，故 `N(L5)=(1,4)`。
各条旧母线仍是整条线，重算后的简写为：

| 整条母线 | 有序双侧名字 | 内部变化位置 |
| --- | --- | --- |
| L1，向右 | `([2,4,1,4],3)` | x=200,450,700 |
| L2，向下 | `(4,[2,1])` | y=200 |
| L3，向右 | `(2,[4,1])` | x=450 |
| L4，向下 | `(4,2)` | 无 |
| L5，向下 | `(1,4)` | 无 |

旧证书、错误方案和正确方案都保存在报告中。JavaScript 与 Python 独立检查分别得到
“合法、冲突、合法”。它说明此前冻结一侧的失败不能用来反驳用户允许重新命名的模型。

## 4. 255 张地图的实际验证范围

固定案例：7 张图库、D/E 两张教学图、3 张旧优先级定向图、D-before 和上述 before/after 三张。
另外 240 张完整生成图：160 guillotine、40 nested-rings-and-bridges、40 boundary-fan。
随机种子 `20260908..20261147`，使用既有 uint32 LCG；不在旧算法阻塞处截断几何。

总计 5,694 条整线（含各图外框）、15,804 条原子实边。检查包括：

- 每条原子实边恰好归入一条母线；5 条虚拟辅助边不被当成母线。
- 原子属性 → 整线有序描述 → 原子属性的往返恢复。
- 反向两次恢复原描述；保留事件位置和顺序。
- Python 根据 rotation 重新建立侧连接轨道，与 JavaScript 几何证书一致。
- 用每侧独立测试符号检查一致性；这里明确不限制到四个符号，不把它算成四色成功。
- D 中新增 x=450 支线前后，`L:0,180>900,180` ID 不变，内部区间从 3 个变成 4 个。

**完全重启的另一项试验：**每张图清空所有旧名，只固定外侧为 1，
沿外框起点遇到的一个内侧为 2。第二个锚定仅消除全局符号置换的对称性。
然后仅传播同侧相等、真正分界不同以及单候选排除规则。

| 结果 | 地图数 | 可作出的判断 |
| --- | ---: | --- |
| solved | 2 | 本轮规则推出完整证书，并检查合法 |
| underdetermined | 253 | 停在多候选；不伪造选择，也不宣称有/无解 |
| conflict | 0 | 只说明这组弱传播尚未发现矛盾 |

这个数字不是通用四色算法成功率，也不是用户完整想法的失败率。
目前实现的只是明确规则的安全子集；本轮没有定义或暗中引入同级候选任选规则。

### 补充调整：消除未用符号整体换名的重复

只固定 1、2 后，3 与 4 仍然全局对称。因此停滞不全是几何困难，也可能只是名字本身未规范化。
新增 `restart_with_symbol_symmetry`：在整线固定读取顺序中，若某线侧候选集合恰好等于
全部尚未使用的名字 U，就用 `min(U)` 作为该处的规范名字。本实验最多需要一次 `{3,4}→3`。
候选 `{1,3,4}` 不能据此任选 1，因为 1 已有含义，不属于同一未用符号对称类。

**安全性理由：**当前约束只有相等/不等和已用名字锚定，所有候选对未用名字的整体置换保持不变。
任何存在的完整解，在该处使用某个 u∈U；把 u 与 `min(U)` 在全图交换，
仍是一个完整解，并保留所有已用名字。故选代表不损失可完成性。
这里没有用“该图必然可四色”作为前提：证明的是“如果有完成解，则规范化后仍有”。
以后若增加指定色名的候选限制，必须重新检查这个全局对称前提。

这一调整仍然不回溯、不枚举配色组合。255 图得到 **7 张 solved、248 张 underdetermined、0 张 conflict**，
每张 solved 都独立检查最终证书。另记录 `symmetry_choices` 与 `non_symmetry_choices`，
不把选了规范代表写成“从未作出任何选择”。

上述 remote 图从外圈清空重算可得：`A=2,R=3,D=4,W=3,E=1`，外侧 1。
先在沿外框遇到的 R 上把 `{3,4}` 规范成 3，随后推出 D=4、E=1、W=3。
因此它不只在条件修复下成立，也能在本轮这一明确的完全重启规则下完成。
这与前述保留 A/R/D 的条件实验不同，报告分别保存，不能混成同一个推导。

## 5. 下一步应调整的规则

1. **整线身份与当前名字分开。** 加线后母线仍贯通；重新计算名字、区间属性和相关依赖。
2. **两侧一起待定。** 不默认保留左边/西边旧名；任何保留条件都显式列出。
3. **检查关联线网，不止接入两端。** 保留闭合接回关系；不能只留下母子树而删掉横向约束。
4. **强制结果直接确定；纯换名重复可取规范代表。** 只有满足上述对称前提才允许后者；
   其他多候选不得暗中任选。处理线和候选集合不等于枚举所有配色方案；本轮无配色枚举。
5. **停滞时保留共同约束。** 每个位置各自有候选，不等于这些候选能同时组合。
   后续可研究基于多个接线端口的兼容关系，但必须说明它是否又引入了组合搜索。

真正尚缺的引理是：在一般允许线网中，指定的新规则如何总能取得进展，并保持四名且终止？
若要无回溯地从多候选中选一个，需要证明该选取保留某个全局可完成解，或给出受限图族证明。
给名字设优先级可以定义确定行为，不能自动得到这个保证。

## 6. 如何复现

Python 核心只使用标准库；几何输入生成器需要项目现有 Node.js 环境。

```bash
python scripts/validate_whole_lines.py --output outputs/whole-line-my-rerun.json
python -m unittest discover -s tests -v
python scripts/validate.py --output outputs/base-validation-my-rerun.json
node --test tests/*.test.mjs
```

整线验证程序拒绝覆盖已有输出；基础 `validate.py` 则应手动指定新的文件名。
本轮正式数据见 `outputs/whole-line-validation-2026-09-18-v3.json`，含输入几何、源文件 SHA-256、
逐例状态、专项整线描述与冲突证书。无版本后缀报告保留首次运行结果；v2 修复布尔值 palette 输入校验，
不改变当时有效输入的统计结果。v3 单独增加全局未用符号对称消除结果，保留纯传播作为对照。

最终回归：Python 135 项通过（整线专项 19 项），Node 99 项通过；
`scripts/validate.py` 的基础有限验证也通过，报告为 `outputs/validation-whole-lines-2026-09-18-v2.json`。
逐一重放 255 图的规范选名步骤，确认候选恰为全部未用名字；重复运行结果完全相同。
基础回归中的旧枚举型测试仅作独立测试 oracle，不被本轮命名函数调用。

局限：浮点交点计算复用既有网站引擎；Python 独立检查 rotation 拓扑和名字，
没有另写精确算术几何引擎。255 例不能取代任意平面图的证明。
本轮不宣称数学原创性、不改许可证、不修改网站选色入口、不上传或部署。
