# 点到点连接：局部接点规则草案

思路发起者：Qinzi27。日期：2026-09-18。

用户进一步澄清：不是先按封闭侧排序赋名，而是从一个已命名结构的接点，
连到另一已命名结构的接点，再更新被改变的母线—子线关系。
此前 `priority-names.js` 只作为侧优先对照，不再声称实现本条规则。

## 基本记录

每条有向几何线段保留独立 ID，属性名是 `(左符号,右符号)`。
端点记录入射线的环绕顺序，以及新线插入的扇区/端口；只有坐标和一个点名不够。
接入旧线中间时，旧线在接点细分，保留来源，不强迫新子段沿用原有全部属性。
母子关系从新网络的选定外圈根重新推导；几何来源与推导父关系是不同记录。
返回已命名结构的闭合连接不能从依赖记录中删除。

## 可证明的局部双 T 模板

两条母线都向右。原上线名 `(a,b)`，原下线名 `(b,d)`。
新增 `P→Q` 竖线向下，西侧暂保留 `b`，东侧取 `c`。
接入后五段的名字为：

```text
上线左段 (a,b) —— P —— 上线右段 (a,c)
                    |
                  (c,b)  向下
                    |
下线左段 (b,d) —— Q —— 下线右段 (c,d)
```

屏幕坐标向下增大；向下线的左侧是东，所以新线不是 `(b,c)`，而是 `(c,b)`。

假设这两处是真正的三侧分界接点，`a≠b` 且 `b≠d`。
上端相容要求 `c≠a,b`，下端要求 `c≠b,d`，合起来：

```text
c ∈ {1,2,3,4} \ {a,b,d}
```

排除的不同符号至多三个，故至少有一个局部候选。
`a≠d` 时三个禁名不同，候选唯一；`a=d` 时有两个候选，不能笼统宣称唯一。
例如 `(a,b,d)=(1,2,4)` 唯一得到 `c=3`，新线 `(3,2)`；
母线上右段变成 `(1,3)`，母线下右段变成 `(3,4)`。

这证明的是**局部两端相容**，且把四标号集当作工作前提；不是从零证明四色上界。

## 属性有限不等于整个结构状态有限

四个符号给出 `4×3=12` 种两侧异名的有向线名。若包括桥，还有四种 `(b,b)`。
它们是可重复的属性类型，不是唯一线 ID。相同 `(a,b)` 可以出现在不同位置。
同一个点可以有多条入射线，需记录循环次序和插入端口；有限字母表不使所有组合网络也有限。

## 不能忽略的连接条件

1. 同名 `b` 不自动表示同一个连通侧，接线前须检查结构连接关系。
2. 跨不同分量的接线可能是桥，两侧应同名，不能硬套真正分割的双 T 模板。
3. 沿途遇到旧线时应拆成多个接点操作。
4. 若东侧沿继承边界还有其他已命名结构，名字 `c` 必须继续传播并检查这些接触；
   端点局部唯一不保证远处也相容。不能只保存一棵发现树而遗漏闭合约束。

一个明确的受限充分条件是：新简单弧内部不碰旧线，确实把同一旧侧 b 分开，
而东子侧全部继承边界的旧对侧名字都属于 `{a,d}`。
此时任意局部候选 c 都不同于全部东侧旧邻名和西侧 b；把东侧所有线侧同步更新，
未受影响边保持不变，故得到全图合法延拓。缺少该边界条件时，只能下局部结论。

下一步应实现端口状态、两端相容候选与命名传播，而不是又换回按闭合侧选优先级。
此处尚未规定一般多分叉时母线继续方向、冲突如何回传、或同级候选的完整选择规则。
